## 문서 변경 후 실행

저장소 루트에서 Node.js 22 이상으로 실행한다. 의존성 설치·제품 빌드·DB·외부 계정이 필요 없다.

```sh
node scripts/ssot-docs.mjs --write
node scripts/ssot-docs.mjs
node --test scripts/ssot-docs.test.mjs
```

`--write`는 CAP·PRD·ADR·DDR·API README의 `ssot-index:start` / `ssot-index:end` 사이만 생성한다. 원문·상태·본문·변경 이력은 자동 수정하지 않는다. 작성자가 원문을 먼저 수정하고, 변경한 인덱스의 `modified_at`·`reason`·Change Log도 함께 갱신한다. 원본에 오류가 있으면 인덱스를 쓰지 않는다.

인덱스는 전체 상태의 문서를 파일별로 한 번씩 포함한다. CAP의 연결 PRD는 각 PRD `capability_refs`의 역참조다. `*-000-template.md`는 등록 문서가 아니므로 제외하며, 실제 문서가 아직 없어도 검사는 통과한다. 부분 대체·완료 근거는 표에 중복 작성하지 않고 원문에서 확인한다.

## 검사 범위

기본 명령은 파일을 쓰지 않는다. 아래 오류가 있으면 종료 코드 1로 실패한다. GitHub workflow도 같은 명령과 회귀 테스트를 실행한다.

- 실제 파일과 인덱스의 누락·중복·제목·상태·버전·관계 드리프트.
- ID·파일명·slug 형식, 000 예약 번호, 중복 ID, 인덱스 표시 필수 필드.
- 상태·lifecycle·우선순위의 허용 어휘.
- PRD의 CAP 연결 누락·잘못된 참조, CAP 상위 관계의 잘못된 참조·순환.
- `depends_on`·`related_prds`·`related_adrs`의 대상 존재 여부.
- 생성 마커의 누락·중복과 생성 구역 밖의 별도 인덱스 행.

템플릿에는 프로젝트별 기존 결함 예외가 없다. 충돌을 발견하면 원문과 참조를 함께 정정한다. 문서 인덱스와 원문 상태가 다르면 원문이 기준이다. 상태를 모른다는 이유로 Active·Accepted·Done을 추정하지 않는다.

## 지원 메타데이터 형식과 한계

검사기는 일반 YAML 전체를 해석하지 않는다. 인덱스에 쓰는 최상위 단일 행 필드와 참조 배열만 읽는다. 배열은 `[CAP-001, CAP-002]` 또는 들여쓴 `- CAP-001` 목록을 사용한다. 문자열은 단일 행이며, 큰따옴표 문자열의 escape는 JSON 호환 형식을 사용한다. `reason`·외부 도구 설정 등 인덱스에서 소비하지 않는 필드는 원문에 그대로 보존한다. 모든 YAML 문법·필수 메타데이터·날짜를 검사한다는 뜻은 아니다.

```yaml
capability_refs:
  - CAP-001
  # 다른 기능과의 연결
  - CAP-002
```

관계 검사는 대상 존재와 CAP 상위 순환에 한정한다. PRD 의존성 순환, 모든 본문 링크·앵커, 디자인 파일 경로, Work Items와 완료 근거의 타당성, 실제 제품 동작은 검토자가 별도로 확인한다. 문서 검사 통과를 제품 완료로 해석하지 않는다.
